It records what was decided, warns whoever's affected, and catches drift from what agents do.

  1. 01

    Captures decisions as they're made

    Straight from agent sessions over MCP — one record_decision call, with an evidence-or-silence rule: no conflict is raised without quoting the decision it breaks.

  2. 02

    Warns everyone affected, before they act

    Computed from who depends on the decision or claims the overlapping scope — including the author's other sessions. Humans resolve; Keel never overwrites.

  3. 03

    Catches drift from what agents do

    Edits, commits and tool calls — checked through Claude Code hooks, not only from what an agent remembers to report. This is the part nothing else does.

The conflict pipeline

Five staged steps, per scope tag, on every write.

  1. 1scope filter
  2. 2vector + keyword retrieval
  3. 3deterministic checks
  4. 4LLM judgment
  5. 5evidence gate

The whole check runs transactionally with the insert, serialized per scope tag — or two concurrent writes on one scope both pass and leave two contradictory decisions with zero conflicts.

Deterministic checks backstop the model; the evidence gate is a hard one. The ledger is append-only, Postgres + pgvector, hash-chained.

FAQ

Questions, answered.

What is Keel, exactly?

An open-source decision ledger for teams and their AI agents. Agents record decisions over MCP; Keel checks each new one against the team's active decisions, and when something contradicts, it quotes the evidence and warns every affected session — before the next action.

Is it production-ready?

Pre-v1. The MCP server, the hybrid conflict pipeline (validated on a real LLM), propagation, handoff and the Claude Code adapter work today, with a ~170-test suite. Treat it as an early build you can run and contribute to, not a stable release.

Which agents does it work with?

Deep tier: Claude Code, through hooks, with guaranteed delivery. Light tier: any MCP agent — Cursor, web apps — best-effort via a piggyback inbox on every tool response. The core is harness-agnostic; Claude Code is the first adapter, not a dependency.

How is it different from a memory store?

It isn't memory. A memory store recalls facts; Keel governs decisions — it detects contradictions, cites the decision they break, and propagates the change to who's affected. It can sit on top of a memory store (Mem0, Postgres, a knowledge graph), not replace one.
